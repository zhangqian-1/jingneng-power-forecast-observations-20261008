# 七站总功率预测测点需求清单

## 1. 使用范围

当前活动模型 `trend_detail_7station_2025_v1`。
调用方按下表提供原始测点即可；请求方式、输出及错误处理见 [接口交接说明](接口交接说明.md)。
七站共 **19 个功率点、8 个温度点、8 个湿度点，合计 35 个输入字段**。
每 15 分钟一个时间点，每次提交完整七站最近一天的 96 点。
19 个功率点先求和形成唯一 `total_power`，不是逐测点预测后再相加。

## 2. 处理规则

| 类型 | 缺失、空值、非数字或非有限值 | 数值 0 / 有限负值 |
|---|---|---|
| 功率 | 按 0，不前值填充、不插值 | 0有效；有限负值逐测点归零后再求和 |
| 温度 | 仅沿用已收到的该点过去真实值 | 保留 |
| 湿度 | 仅沿用已收到的该点过去真实值 | 保留 |

功率有效性以该时刻原始功率测量是否全部存在判定，补零不算实测完整。
本表的缺失补0用于预测输入；独立实测接口缺测不补0，负功率同样逐测点归零。模型权重不变，功率预处理规则与旧版不同。
温湿度先按测点因果填充，站内平均，再七站平均。
某天气点尚无历史观测时不能用未来值初始化；继续存储请求。平台接口连续可用历史不足672点时返回HTTP 200和空 `result_point`，通过 `reason` 区分历史不足和天气不可用。
可先顺序补传更早真实历史，或等待采集条件满足。清单必须列全35个测点；未知、重复或清单遗漏的测点返回400。清单完整而某帧缺值时，推荐写 `null`，也兼容省略该帧测点字段。
此版本不含深圳钰湖、钰海电力、京宜热电，不做这些场站的温度换算。

## 3. 场站与测点

### 3.1 填写说明

顶层 `point_table` 列出下表全部35个原始编码。`frames`包含96条，每条带 `timestamp`，并直接以测点编码为字段名填写数值，不嵌套场站或 `load_points` / `weather_points`。保留编码中的点号与冒号。

具体写法看 [完整平台输入样例](../examples/platform_input_example.json)，其他字段见 [接口说明](接口交接说明.md)。用户已确认历史训练数据使用北京时间（`Asia/Shanghai`）；平台输入、输出均为UTC，服务内部转换为北京时间。输出时间格式与请求一致；平台已发UTC时不要重复换算，目标服务器验收范围见接口说明。

## 4. 调用方是否需要补充特征

上述 35 个测点都参与当前模型的数据构造，不是只需要功率。调用方不必计算总功率、平均温湿度、状态或时间特征，这些由服务处理；也不需要传未来实测天气。服务使用历史缓存，不在线训练。
