# 七站总功率预测平台接口说明

当前模型为 `trend_detail_7station_2025_v1`。本版统一使用平台接口，不重新训练模型。输出为七站合计功率的一条96点序列，单位MW，不是7站或19个测点分别预测。

**时间规则：历史训练数据使用北京时间（`Asia/Shanghai`）。接口收发UTC，模型内部按北京时间构造时间特征；输出时间格式与本次请求一致。**

## 1. 请求方式

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/fluxcast/compute` | 接收历史测点，缓存就绪后预测未来96点 |
| GET | `/api/v1/fluxcast/compute/latest` | 查询本接口最近一次成功结果，不触发预测 |

端口默认8000，地址由部署方提供。请求头为 `Content-Type: application/json`，Body为UTF-8 JSON。Compose默认仅允许本机访问，其他机器通过配置好的网关或内网地址调用。服务不内置鉴权和HTTPS，由部署平台负责。

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/fluxcast/compute" -H "Content-Type: application/json" --data-binary @examples/platform_input_example.json
```

Windows PowerShell使用 `curl.exe`。`@文件路径` 表示调用方读取文件并发送内容，不是把路径交给服务。平台也可以直接组装JSON，无需创建文件。

## 2. 输入字段

| 字段 | 类型 | 要求 |
|---|---|---|
| `point_table` | string数组 | 七站全部35个原始测点编码，无重复、无未知编码；顺序不限 |
| `frames` | 对象数组 | 必须96条，表示最近一天历史实测值，不是未来预测值 |
| `frames[].timestamp` | string | UTC日期和时间，96帧格式一致；连续、不重复、对齐15分钟；支持格式见下文 |
| `frames[][测点编码]` | number或null | 测点直接作为frame的key；功率MW、温度摄氏度、湿度% |

每个时刻提交完整七站快照：19个功率、8个温度、8个湿度。编码见 [测点需求清单](测点需求清单.md)，保留 `.` 和 `:`，不替换为下划线。不嵌套 `stations`、`load_points`、`weather_points`。

缺测推荐显式写 `null`（不加引号），也兼容省略该帧的测点字段；两者均按缺测处理。`point_table`仍须列全35个编码，`timestamp`不能省略。正常测量值不带单位或百分号；布尔、非数字及非有限值按缺测处理，JSON不要写非标准的NaN或Infinity。

本服务按全七站接收，无需 `source_id`。`renewable_data` 是调度算法的数据，本预测接口不要求、不读取它，不将它作为模型特征。不会代为调用新能源API。

预测调用频率沿用原流程，可每天生成一次未来24小时曲线；初始化时可按日期从早到晚补传。数据在请求内可按时间排序后校验，不允许重复时间或缺少整条记录。无未来天气输入要求。新增的每15分钟单帧实测请求使用独立接口，见 [实测接口说明](实测接口说明.md)，不改本预测接口。

### 时间约定

平台收发UTC，不要求增加时区字段。输入使用完整的 `YYYY-MM-DD HH:mm:ss` 或 `YYYY-MM-DDTHH:mm:ss`，可不带后缀，或使用 `Z`、`+00:00`、`+0000`；无后缀也按UTC理解。支持1至9位小数秒，但对齐15分钟整刻时小数必须全为0。显式非零偏移（如 `+08:00`）返回400，调用方应先转换成UTC。

输出保留请求的日期时间分隔符、小数秒位数及UTC后缀，不统一改写为空格格式。同一请求的96帧必须使用相同格式，混用返回400且不写入缓存；不同请求可以切换格式。

| 请求末点（UTC） | 预测首点（UTC） |
|---|---|
| `2025-10-19 15:45:00` | `2025-10-19 16:00:00` |
| `2025-10-19T15:45:00Z` | `2025-10-19T16:00:00Z` |
| `2025-10-19T15:45:00.000+00:00` | `2025-10-19T16:00:00.000+00:00` |

服务在缓存及构造模型特征前将UTC转换成北京时间，完整转换年月日、小时、星期；预测目标时间再转回UTC。数值及其对应时刻不变，也不修改原CSV、权重或模型融合参数。该行为不依赖服务器操作系统时区。

例如输入末点为 `2026-09-21 02:00:00` UTC，模型内部对应 `2026-09-21 10:00:00` 北京时间；第一条预测返回 `2026-09-21 02:15:00` UTC，共96点。平台已发UTC时无需额外平移。

## 3. 缓存和缺测

| 情况 | 处理 |
|---|---|
| 功率缺测 | 按0；真实0有效，有限负功率逐测点归零后再求和，不沿用历史功率，不插值 |
| 温湿度缺测且存在该点过去真实值 | 因果前向填充，不用未来值倒填，不假定天气为0 |
| 连续可用历史不足672点 | 本次数据仍缓存，HTTP 200和空结果，原因 `history_not_ready` |
| 天气尚不能构造完整连续历史 | 本次数据仍缓存，HTTP 200和空结果，原因 `weather_history_not_ready` |

重复时间的功率以最新快照为准，最新缺测则补0；天气保留该时刻最新非空观测，再向后填充。重复请求不增加历史点数。时间中断会重新累计连续历史，不自动造时间记录。请求末点早于已有缓存末点，或请求早于保留范围，返回400。

本版默认使用 `/app/runtime/history_7station_2025_v1_utc_to_asia_shanghai_v1.csv`，缓存时间为模型北京时间；最近成功结果保存到 `/app/runtime/latest_forecast_utc_to_asia_shanghai_v1.json`，响应时间为UTC。最多保留768点及历史上下文。缓存和最近结果均校验时间规则版本 `utc_to_asia_shanghai_v1`；旧缓存改名仍会拒绝，旧最近结果不会返回。升级后用UTC重新补传历史，至少672个连续可用点才能预测。容器重建须保留本版runtime；不允许多个服务实例同时写同一缓存文件。

可通过 `--history-cache`、`--latest-json` 指定路径，两者不能重合。仅保留这一套缓存与结果，旧版本缓存不会自动导入。

功率处理规则同时校验 `point_negative_to_zero_v1`。升级本规则时使用新的预测runtime目录，并按UTC重新补传至少7天连续可用历史；不要把旧CSV改名复用，其中的状态上下文按旧规则计算。旧目录保留备份，实测SQLite归档不需清空。

## 4. 响应字段

成功返回HTTP 200：

| 字段 | 含义 |
|---|---|
| `result_point` | 96条 `totalPowerForecast` 预测，另含 `forecastPointCount`、`forecastIntervalMinutes` 两条统计 |
| 预测条目的 `timestamp` | 输入最大时间后15分钟开始的未来96点，UTC，格式与本次请求一致 |
| 预测条目的 `value` | 有限浮点数，MW，保留四位小数 |
| `extra_info` | `forecastBatchId`、`forecastGeneratedAt`、`forecastStartAt`、`forecastEndAt`，value均为字符串 |
| `event_key` | 沿用平台文档的 `JNH.Fluxcast.Compute`；平台接收端须注册相同名称 |

`(varname, timestamp)`组合唯一。输出不包含调度费用、碳排放或实时准确率。当前预测精度须等对应实测到达后评估，不输出固定的历史参考 `accuracy`。

完整变量定义见 [返回字段说明](返回字段说明.md)。前端按varname筛选预测，不再将整个 `result_point` 数组都当作曲线。生成时间是真实运行时间，不是历史回放时间；GET及重启不重新生成批次。

暂时无法预测时仍为HTTP 200，`result_point: []`、`extra_info: []`，并附：

| 字段 | 含义 |
|---|---|
| `reason` | `history_not_ready` 或 `weather_history_not_ready` |
| `message` | 给人阅读的原因说明，平台程序应判断reason而非匹配中文文本 |
| `continuous_points` | 当前连续可用点数；天气尚不可用时可小于实际已缓存点数 |
| `required_points` | 固定672 |
| `missing_weather_points` | 导致当前可用历史缩短的天气测点编码；无则为空数组 |

**HTTP 200不等于预测成功，必须检查 `result_point`。** 不返回 `value: null` 的伪预测记录，无法预测时直接返回空数组。缺测填充、空结果和内部故障写服务日志。

GET `latest`只返回最近一次成功预测，保留该次请求的时间格式，服务重启后也不改写；后续空结果不会覆盖它。首次无结果返回404；调用方必须核对预测目标时间，不能把较早的成功结果当作本次新预测。

## 5. 错误响应

| HTTP | 原因 | 处理 |
|---|---|---|
| 400 | `invalid_request` | JSON、清单、时间或批次错误；本次不入缓存，修正后重发 |
| 404 | `no_forecast`（新接口latest） | 尚无本模型的平台预测；继续补真实历史 |
| 413 | `request_too_large` | 请求超过50 MiB |
| 500 | `prediction_failed` / `latest_result_unavailable` | 计算、存储或读取故障；查看日志，不当成正常预热 |

新接口错误也包含 `event_key`、空 `result_point`、`reason`、`message`。新接口不以409或422表达缺测/预热。计算失败前有效数据可能已缓存，修复后可重发同一批次。未知路由返回404。

| 样例 | 用途 |

输入样例来自真实历史观测，时间已换算为UTC；成功输出来自当前模型。生成时间是实际运行时间，与2025年的预测目标时间不同，批次ID也会随重新计算变化。复现成功样例需先按UTC补传北京时间2025-10-06至10-19的历史，不能仅向空缓存提交最后一天。天气缺失样例将一个测点置null，用于说明对应的空结果响应。

## 7. 版本使用

本版只保留上述平台接口和六个JSON样例，旧接口不再提供服务。旧版代码保存在Git历史中，不混入当前源码目录。此前GitHub的 `042dcd1` 镜像不包含本次改动；本版须重新构建并验收。
