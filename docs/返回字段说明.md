# 功率预测与实测返回字段

本文件是后端对接的变量字典。预测和实测分别调用两个POST接口，输入格式保持 `point_table + frames`。预测接口接收35个测点、96帧历史；实测接口接收19个功率测点、1帧，不触发预测。

## 1. 通用结构

| 字段 | 规则 |
|---|---|
| `result_point` | 数值条目数组；每项包含 `varname`、`timestamp`、`value`；value为有限浮点数，计数也使用96.0等浮点数 |
| `extra_info` | 字符串条目数组；结构同上，value只能是字符串 |
| `event_key` | 固定 `JNH.Fluxcast.Compute` |

通过 `varname` 识别变量，通过UTC时刻对齐；不要按数组下标或数组总长度识别预测曲线。`(varname, UTC时刻)` 组合唯一。所有时间都按UTC解释，保留请求的时间格式；不要求额外增加Z。不可计算的数值整条省略，不使用null、字符串或占位0。

## 2. 预测接口

`POST /api/v1/fluxcast/compute`，默认端口8000。成功响应有96条预测、2条统计和4条字符串信息。

| 位置 | varname | value含义／单位 | timestamp含义 |
|---|---|---|---|
| result_point | `totalPowerForecast` | 七站总功率预测，MW，共96条 | 每条预测的UTC目标时刻，间隔15分钟 |
| result_point | `forecastPointCount` | 本批预测点数，96.0 | 预测生成时刻 |
| result_point | `forecastIntervalMinutes` | 预测间隔，15.0分钟 | 预测生成时刻 |
| extra_info | `forecastBatchId` | 本次成功计算的唯一编号，形如 `dayahead-` 加32位标识 | 预测生成时刻 |
| extra_info | `forecastGeneratedAt` | 预测实际生成的UTC时间字符串 | 同value |
| extra_info | `forecastStartAt` | 第一条预测的UTC目标时间字符串 | 预测生成时刻 |
| extra_info | `forecastEndAt` | 最后一条预测的UTC目标时间字符串 | 预测生成时刻 |

生成时间取服务器完成预测的时刻，不是历史数据末时刻或平台拉取时间，因此无需对齐15分钟。每次成功计算产生新批次；GET `/api/v1/fluxcast/compute/latest` 和服务重启保留原批次及生成时间。回放2025年数据时，目标时刻属于2025年，生成时间仍是实际运行日期。

历史不足或天气不可用时，HTTP 200、两个数组均为空，保留原顶层 `reason`、`message`、连续点数等字段，不创建虚假批次。详见[预测接口说明](接口交接说明.md)。

## 3. 实测接口

`POST /api/v1/fluxcast/observations`，默认端口8002。下列条目的timestamp均为本次请求的UTC采集时刻。

| 位置 | varname | value含义／返回条件 |
|---|---|---|
| result_point | `totalPowerActual` | 七站19点完整且合计为有限数时返回功率，MW |
| result_point | `totalPowerDeviation` | 同UTC目标时刻的预测减实测，MW；实测合计可计算、有符合条件的预测且偏差未溢出才返回；可负、可0 |
| extra_info | `dataStatus` | 全部19点的数据完整性，见下表 |
| extra_info | `missingPoints` | 缺测时返回不可用测点编码，以英文逗号分隔 |
| extra_info | `reason` | 有结果无法计算时的主要原因码，取值见[实测接口说明](实测接口说明.md#3-输出字段与返回规则) |
| extra_info | `message` | 与reason一起返回；说明相关测点、不可用原因和值摘要，以及因此未返回的varname；用于说明，不作为固定文本解析 |
| extra_info | `forecastBatchId` | 本次偏差使用的预测批次；新格式归档且成功计算偏差才返回 |
| extra_info | `latestActualAt` | 本服务已保存的、七站完整且总功率可计算的实测中最新UTC采集时刻；没有符合条件的实测则省略 |

`latestActualAt` 不是服务器收到请求的时间。迟到补传不会让它倒退；若修正数据使原最新时刻变为缺测或合计溢出，会重新选择剩余可计算完整实测的最大时间。本次功率的时间仍以该条目的timestamp为准。

每站使用固定前缀：`GARD`高安屯（3点）、`JXRD`京西（5点）、`JYRD`京阳（3点）、`JQRD`京桥（3点）、`JFRD`京丰（1点）、`WLRD`未来（2点）、`SZRD`上庄（2点）。以下以京西为例，七站规则相同。

| 位置 | varname示例 | value含义／返回条件 |
|---|---|---|
| result_point | `JXRD_powerActual` | 该站所有功率点有效且合计为有限数才返回，MW |
| result_point | `JXRD_powerShare` | 该站出力÷七站总功率×100；34.5表示34.5%；七站完整、合计可计算且总功率>0才返回 |
| result_point | `JXRD_validPointCount` | 本次有效测点数，0.0至5.0，每次返回 |
| result_point | `JXRD_requiredPointCount` | 应有测点数，5.0，每次返回 |
| extra_info | `JXRD_dataStatus` | 该站数据完整性，每次返回 |
| extra_info | `JXRD_missingPoints` | 该站缺测时返回不可用测点编码，以英文逗号分隔 |
| extra_info | `JXRD_reason` | 极端输入导致站内合计溢出时为 `power_sum_out_of_range`，该站功率省略 |

| dataStatus | 含义 |
|---|---|
| `complete` | 应有测点全部有效，真实0有效，有限负功率归零后也有效 |
| `incomplete` | 部分测点不可用 |
| `missing` | 所有测点不可用 |

状态描述数据完整性，不表示设备健康，也不保证聚合结果未溢出。尚未收到某时刻数据由平台自行判断。部分缺测时保留其他可计算站的出力和各站计数，不返回七站总功率、偏差及任何占比。全部缺测仍返回各站计数和状态。七站全部为0时返回总功率0.0和各站功率0.0，占比省略。缺测或计算失败仅省略受影响结果，原因和字段清单写入message及服务日志；后端按varname是否存在判断，不以0代替缺失结果。展示时可四舍五入，不要用展示后的站值重新求合计。

偏差采用同一UTC时刻、且在该时刻之前已生成并归档的预测。选定批次后，补传修正实测继续关联原批次。旧归档没有公开批次ID时可继续匹配，但不伪造ID或生成时间。实测接口不额外返回同刻预测值，平台可用批次和timestamp查询已保存的96点曲线。

## 4. 功率处理与范围

预测输入和实测输入都先逐功率测点执行 `max(原值, 0)`，再进行站内及七站求和；不得先求和再把负总和归零。温度、湿度以及预测偏差不应用这条功率归零规则。缺测不同于负功率：预测侧缺失功率仍补0，天气仍只用过去真实值前向填充；实测侧缺测不补0。

本服务不返回去年同期值、同比、数据覆盖率、页面固定文字、前端拉取时间或额外的同刻预测副本。去年同期与覆盖率由平台历史库处理。预测点数可同时用于页面“结果条数”，不要把新增统计项计为预测点。
