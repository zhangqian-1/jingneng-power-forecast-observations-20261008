# 实测功率与预测偏差接口说明

## 1. 调用方式

`POST /api/v1/fluxcast/observations`，默认端口 `8002`，请求头 `Content-Type: application/json`。

平台每15分钟推送一次七站同一时刻的19个功率测点，服务返回各站出力、占比、完整性状态、总功率及可计算的预测偏差。本接口不触发预测。

## 2. 输入字段

| 字段 | JSON类型 | 是否必填 | 要求 |
|---|---|---|---|
| `point_table` | 字符串数组 | 是 | 列全19个功率测点编码，不重复，保留编码中的点号和冒号 |
| `frames` | 对象数组 | 是 | 每次恰好1帧 |
| `frames[].timestamp` | 字符串 | 是 | 数据采集时刻，使用UTC，须对齐15分钟整刻 |
| `frames[].测点编码` | 数值或 `null` | 允许缺测 | 对应功率值，单位MW；缺测填 `null` 或省略该字段，真实0有效，有限负值逐测点归零后求和 |

不传温湿度，也不传预先求和的总功率。即使某个测点缺测，`point_table` 仍需列全19个编码。

功率应使用有限JSON数值，不要加引号；字符串、布尔值等非数值按缺测处理。NaN、Infinity不是合法JSON，请用 `null`。

时间支持 `2026-11-25 05:00:00`、`2026-11-25T05:00:00Z` 及 `+00:00`/`+0000` 后缀；无后缀也按UTC，不接受非零时区偏移。分钟为00、15、30、45，秒为0；如有小数秒须全为0，最多9位。响应保留请求时间格式。

## 3. 输出字段与返回规则

以下说明适用于HTTP 200响应。固定返回 `result_point`（对象数组，可为空）、`extra_info`（对象数组）和 `event_key`（字符串，固定为 `JNH.Fluxcast.Compute`）。两个数组中的每个条目均包含：

| 条目字段 | JSON类型 | 返回条件 | 含义 |
|---|---|---|---|
| `varname` | 字符串 | 每项必返 | 变量名称，同一数组内唯一 |
| `timestamp` | 字符串 | 每项必返 | 对应本次实测的UTC采集时刻，保留请求格式 |
| `value` | 数值或字符串 | 每项必返 | `result_point` 中为浮点数，`extra_info` 中为字符串 |

例如 `dataStatus` 是 `varname` 的取值，`complete` 是对应的 `value`，不是在响应顶层增加 `dataStatus` 字段。

| 位置 | varname | 返回条件 | value含义 |
|---|---|---|---|
| `result_point` | `totalPowerActual` | 19个功率值全部有效且合计可计算 | 19点之和，单位MW |
| `result_point` | `totalPowerDeviation` | 实测完整、有同刻有效预测且偏差未溢出 | 预测值减实测总功率，单位MW，正值表示预测偏高 |
| `extra_info` | `dataStatus` | 每次HTTP 200响应均返回 | `complete`：19点有效；`incomplete`：1至18点有效；`missing`：全部不可用 |
| `extra_info` | `missingPoints` | `incomplete` 或 `missing` 时返回 | 逗号分隔的不可用测点编码字符串 |
| `extra_info` | `reason` | 有数值结果无法计算时返回 | 主要原因码，见下表 |
| `extra_info` | `message` | 与reason一起返回 | 具体测点、不可用原因及受影响的varname；多种原因会一并说明 |
| `extra_info` | `forecastBatchId` | 使用新格式预测成功计算偏差 | 与预测接口相同的批次编号 |
| `extra_info` | `latestActualAt` | 已保存过可计算总功率的完整实测，且修正后仍可计算 | 这些实测中最新的UTC采集时刻，不是请求到达时间 |

此外每站返回出力、占比、有效/应有测点数和数据状态，命名如 `JXRD_powerActual`、`JXRD_powerShare`、`JXRD_validPointCount`、`JXRD_requiredPointCount`、`JXRD_dataStatus`、`JXRD_missingPoints`。全部字段及条件以 [返回字段说明](返回字段说明.md) 为准。

| reason取值 | 含义 | 返回数值 |
|---|---|---|
| `missing_power_points` | 测点缺字段、null、类型错误或数值不可用 | 保留其他完整站出力、各站计数；省略受影响站出力、七站合计、偏差及各站占比 |
| `power_sum_out_of_range` | 有限输入求和后超出数值范围 | 仅省略溢出的合计及依赖它的结果；其他可计算站出力和计数仍返回 |
| `no_matching_forecast` | 没有符合条件的同刻预测 | 实测与各站统计，不返回偏差 |
| `deviation_out_of_range` | 偏差计算超出有限数值范围 | 实测与各站统计，不返回偏差 |
| `total_power_zero` | 七站实测合计为0，占比无法计算 | 返回总功率0及各站功率0，偏差可计算则返回，仅省略占比 |

`dataStatus` 只表示输入完整性，`complete` 不保证合计、偏差都可计算。后端按varname是否存在展示数值，不要把未返回当作0；`message` 用于说明，不依赖其文本格式做判断。多种原因并存时，reason优先说明缺测或合计溢出，其次偏差不可用，最后零总功率；message列全原因。服务日志记录UTC时刻、相关测点及值摘要、原因和未返回字段。

- 19点完整且合计为有限数才返回总功率。缺测不补0、不返回不完整的七站合计；其他可计算站仍返回出力，各站计数和状态仍返回。真实0、有限负值归零后均计为有效点，不标异常；全部为0时占比省略并说明原因。
- 偏差仅使用目标时刻前已归档的**同一UTC时刻**预测；没有可用预测时，只返回实测总功率，不返回偏差。
- 补传使用数据原本的采集时间，不使用发送时间。重复提交同一时刻会更新实测值。
- 数据缺测、单点值不可用、计算溢出或无匹配预测返回HTTP 200；请求格式、测点编码或时间不合法返回HTTP 400。NaN/Infinity字面量不属于合法JSON，仍返回400，请传null。不可用的数值变量整条省略，不返回缺少 `value` 的条目，也不用0或null占位。

本接口的JSON错误响应中，`result_point`、`extra_info` 均为空数组，顶层 `reason` 和 `message` 为错误码与说明字符串，不属于上述HTTP 200的业务变量。

## 4. 完整JSON样例

下列文件位于生产部署包根目录的 `examples/`，`observations_` 前缀表示实测接口，`platform_` 前缀仍为原预测接口。

| 样例 | 文件 |
|---|---|
| 完整输入：19个功率测点、1帧 | [observations_input_example.json](../examples/observations_input_example.json) |
| 完整输出：实测总功率和偏差 | [observations_output_example.json](../examples/observations_output_example.json) |
| 无匹配预测：实测与各站统计，不含偏差 | [observations_output_no_forecast.json](../examples/observations_output_no_forecast.json) |
| 部分缺测：保留完整站出力、计数及缺测状态 | [observations_output_incomplete.json](../examples/observations_output_incomplete.json) |
| 全部缺测：各站计数及缺测状态 | [observations_output_missing.json](../examples/observations_output_missing.json) |

完整输入的合计为1795.0 MW；含偏差的输出样例假设同刻有效预测为1850.0 MW，因此偏差为55.0 MW。数值仅用于说明格式，不是固定返回值。未保存可用预测时，返回无匹配预测的形式。

部分缺测输出对应输入样例中首个功率测点设为 `null`；全部缺测输出对应19个功率值全部设为 `null`。

例如首个测点为null时，`message` 指明该编码及 `null` 原因，列出未返回的 `GARD_powerActual`、`totalPowerActual`、`totalPowerDeviation` 和七站 `powerShare`；其他六站出力仍返回。预测侧功率缺失补0的规则不变。

在生产部署包根目录调用：

```bash
curl -X POST "http://127.0.0.1:8002/api/v1/fluxcast/observations" -H "Content-Type: application/json" --data-binary @examples/observations_input_example.json
```

地址和端口以部署方提供的配置为准；Windows PowerShell使用 `curl.exe`。
